## 一、已有交互（已确认存在）

### 1. 聊天框出现 → 弹走机器人

聊天面板展开时，站在它将要覆盖的区域里的机器人会被沿抛物线「撞」向左下角。
已经不在覆盖区内的机器人保持原地，不会被无谓地挪走。

- 触发：`obstructed` 转为 true（由 `explore-map-page.tsx` 传入 `chatOpen`）。
- 覆盖区判定：地图面板的右下象限（水平 50% 之后、垂直 35% 之下）。
- 例外：正在被拖拽时不触发。

### 2. pin 地点 → 机器人冒出地点

选中/pin 一个地点后，机器人身旁弹出对话云，内容是该地点的名字（例如「上海」）。
云的方向按机器人当前位置重新计算：头顶空间不足时翻到下方。

- 触发：`speechPlace` 由 `selected?.name` 传入，非空即显示。

### 右键单击 / 右键双击（已解决）

一度担心这两条互斥：双击必然先经过一次单击，如果右键单击直接跳转，人就被带走了，
右键双击永远触发不到。

**弹菜单的设计把这个问题消掉了**：右键单击只是弹一个菜单——无害、可撤销、
不离开应用；真正的跳转发生在人点了菜单里的「退出」之后。所以给右键加约 300ms
的判定窗口不付任何代价，双击可以在菜单弹出前把它取代掉。跳转用新标签页，
聊天正在跑的那一轮不会丢。

## 五、结构方案

现有 `wander-bot.tsx` 已经 479 行，做的全是定位物理。十几个彩蛋塞进去会立刻失控。
拆成四层，彼此不互相污染：

| 层 | 职责 | 为什么单独一层 |
|---|---|---|
| 身体层（现有文件） | 位置、拖拽、栖停在输入框上、被弹飞、眼神跟随 | 彩蛋完全不碰它，已有交互不会被改坏 |
| 形象层 | 当前是哪个角色（robo / 啥子 / …），纯展示 | 你的 UI 图到位后直接替换素材，不动行为 |
| 手势层（纯函数） | 把指针事件翻译成命名手势：`clickRun(n)`、`drag`、`rightClick`、`rightDoubleClick`、`onTheHour` | 不碰 DOM，可以写单测。0.7s 断点、右键窗口这些规则全锁在这层 |
| 彩蛋表 | `(角色, 手势) → 效果 + 冷却`，是**数据不是分支** | 加一条彩蛋 = 加一行。上面那些「待你补」的空格现在可以先空着 |

全屏类效果（颠倒、指针）放在独立覆盖层组件里，机器人自己不改全局 CSS。

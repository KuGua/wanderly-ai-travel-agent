# 登录后首页原型参考

`assets/reference-homepage.html` 是 Travel Together **登录用户首页**的独立静态参考。它**不是**营销/介绍页、应用运行时、API 契约或部署方案。

## 目的

它将当前产品文档转化为回访旅行者看到的第一个工作台。信息层级刻意采用行动优先：

1. 用户先看到当前共享行程是否需要自己处理；
2. 可以继续私有 Personal Agent 对话；
3. 可以检查个人待办和范围化共享状态；
4. 可以区分稳定的私有偏好与本次行程范围内的共享偏好。

它还表达 MVP 的核心承诺：

- 每位旅行者保留可编辑的私密资料；
- 只有明确、行程范围内的授权进入共享工作台；
- 协调后的选项解释价格、服务和偏好取舍；
- 变化会使旧方案过期并展示重规划差异；
- 预订编排绝不自动扣款或自动预订。

地图空白区域支持单击探索：页面会放置一个临时探索标记，并打开地点档案。若该位置不是预置候选，档案只允许用户将其保存为私有灵感或请求后续加入候选；它明确说明当前没有可验证的候选资料，不会编造地点、价格、库存或入境信息。已有候选的地点标记仍可直接打开其 fixture 支撑、带 `Demo data` 标签的档案。

展示的是 Alice 的视觉示例：里斯本方案因价格变化已重规划，正等待复核。页面内所有人物、目的地、价格、时间和状态均为示意内容；产品运行时的旅行事实必须来自 API，provider 无数据时显示 `UNAVAILABLE`，不是实时可用性、库存、法律指引或预订数据。

## 运行与验证

直接在现代浏览器中打开 `assets/reference-homepage.html`。无需服务器、软件包、环境变量或后端服务。

验证 375px、768px、1024px、1440px 布局，然后使用键盘导航。链接和按钮应保持可见焦点，文档提供跳转链接；启用减少动态效果的用户不会看到非必要动画。

## 边界

该原型不会调用后端、存储个人数据、认证用户、请求授权、运行规划或发起预订。探索标记仅存在于当前页面内，刷新后即消失。未来的生产界面必须从 PRD 和 `TECH_STACK.md` 所述的服务端权威模型中获取所有展示的方案、授权、状态和确认数据。

# Wanderly 原型设计规范

## 范围

本文记录当前静态原型已采用的设计语言，作为后续原型和前端实现的视觉参考：

- `assets/projects-prototype.html`：项目列表；
- `assets/project-workspace-prototype.html`：项目对话与工作区；
- `assets/explore-map-prototype.html`：地图探索（宇宙变体）。

这些文件仅展示交互和视觉方向，不改变产品的 API、授权、计划状态或预订边界。

## 设计方向

整体是克制的手绘描边漫画风：像旅行手帐中的墨线、纸张和贴纸，而不是扁平企业面板。轮廓带来明确层级，轻微不规则的圆角和错位投影保留手作感；颜色集中用于表面、路径和状态，正文不使用彩色字。

桌面端采用一张从顶部到接近底部的窄长导航浮窗。它是导航锚点，不应把内容压缩进侧栏宽度；沉浸式地图可铺到浮窗下方，不应在其后保留页面底色的侧栏留白。移动端再退化为正常的顶部导航条。

## 色彩与语义

| Token | 色值 | 用途 |
| --- | --- | --- |
| `--moss` | `#67768f` | 次级冷灰蓝、纹理与低强调表面 |
| `--primary` | `#404e5b` | 导航浮窗、深色结构面、宇宙深空基调 |
| `--info` | `#599db5` | 信息图形、插画面与地图星云 |
| `--highlight` | `#65bbb0` | 主操作、选中导航、航迹和互动高光 |
| `--fog` | `#f1edea` | 纸张基调、浅表面、暗色场景中的文字与星光 |
| `--white` | `#fff` | 普通页面的主要内容表面 |
| `--ink` | `#1d1d1b` | 文字、描边、按压投影与可见焦点 |

普通页面以浅雾白纸张为底，使用深色文字。深色宇宙地图是例外：把 `--primary` 与黑色混合为深空，不增加新的品牌色；`--info` 是星云，`--highlight` 是航迹与交互高光，`--fog` 只用于文字与星点。宇宙场景中的浮层必须是半透明深色，不能回退为白卡。

## 核心视觉规则

- 正文与标题使用 `--ink`；深色宇宙浮层使用 `--fog`。不要用品牌色给文字上色。
- 可交互或承载内容的元素使用 1.5–2px `--ink` 描边；深色宇宙浮层可改用半透明雾白描边以保持可见性。
- 圆角避免完全规整，例如 `24px 17px 26px 16px`；同层组件可以有轻微差异，但不应影响点击边界。
- 关键卡片和按钮采用硬边投影，例如 `4px 4px 0 var(--ink)`。悬停/按下时将投影缩短并平移 1–2px，形成按压反馈。
- 页面背景使用低对比度颗粒纸纹；纹理不得降低文本对比度或承载信息。
- 图标保持统一的 SVG 描边风格，交互控件必须有可读的无障碍名称。

## 组件约定

### 侧边导航

桌面端：固定定位，`top: 18px`、`bottom: 18px`、`left: 14px`、`width: 64px`，深色底、浅色内部按钮、黑色描边和硬投影。选中项使用 `--highlight`，同类导航按钮保持相同颜色与尺寸。

移动端：在 720px/760px 以下转为 62px 高的顶部导航条，取消浮窗外阴影。页面主内容必须明确回到第一列。

### 普通卡片、按钮和标签

普通页面卡片使用白色或雾白表面；边框、轻微不规则圆角和硬边投影提供层级。需要纸张感的非关键卡片可在单个底角使用约 50–75px 的曲线翻页装饰：前表面应保持几乎完整，仅在角尖自然过渡到回卷；背面使用同一中性色板的低对比渐变，并在尖端下方投下局部轻微阴影。卷角必须在内容层下方且 `pointer-events: none`，不得遮挡按钮或承载信息。主按钮使用 `--highlight`，悬停时可转为 `--info`，文字仍保持深色。状态不只依赖颜色，应同时保留文字标签。

### 对话与工作区

对话气泡、信息窗、计划卡与资料窗使用相同的描边语言。右侧内容检查器不设置独立的“工作区”标题文字，但保留一条与对话 Header 对齐的无标题分割栏；其下从上到下排列方案比较、路线资料和探索地图，地球预览不得吸附在底部。用户消息可使用 `--info` 填充，Agent 消息使用浅表面；不要引入新的高饱和状态色。项目下的每个会话必须呈现为独立 Tab 卡片，具备边框、硬边投影、时间标签和清晰的当前会话标识。长文字区域需要 `min-width: 0`、截断或换行策略，不能撑破列宽。

### 宇宙探索地图

地图画布以纯深空和固定星点营造空间感，并保留机器人、航线和抽屉的原有功能。不要以光束、阴影、星云或径向渐变制造背景光晕。身份栏、引导卡、抽屉、城市快捷按钮、步骤卡与地图控件均使用深色半透明表面；星点只作装饰且 `pointer-events: none`，不能遮挡地图操作，也不应移动。

Agent 对话面板同样是宇宙浮层，不是被重新着色的浅色对话窗：面板本身用 `wanderly-cosmos-panel`，其中的消息气泡、内联操作卡和输入框用比面板更深一档的 `wanderly-cosmos-surface`，头部与输入区的分割线用 `--space-line` 而非 `--ink`。深空场景由此形成三段层次：场景 / 面板 / 面板内内容。硬边投影在宇宙中仍然是 `--ink`，只有描边转为雾白。折叠态的输入条是同一个控件的前一个状态，必须与展开后的输入框用同一种材质；给它浅色纸卡会让「打开对话」读起来像换了一个产品。

宇宙浮层的填充朝 `--info` 掺色，不朝黑色掺。朝 `#000` 掺会把色度抽干，面板变成灰死的盒子，对一个讲「去远方」的产品是错的音调；朝信息蓝掺则在保持足够暗、雾白文字对比度充裕的同时留住蓝。填充同时是真正半透明的，地球与星点透过面板继续存在，而不是被一堵墙挡掉。

半透明的代价是有效背景会随身后内容变化：地球亮处会把背景抬亮，雾白文字可能跌破 AA。解决办法是在 `backdrop-filter` 里先 `brightness()` 压暗背后再合成，而不是提高填充不透明度换取安全：前者保住通透感，后者不保。取上界验算（面板背后为纯白时）：面板上雾白文字 4.95:1，气泡上 9.06:1，均过 AA。`prefers-reduced-transparency` 下没有 blur，半透明填充只剩淡色，因此该分支必须回退为不透明填充。

同一个对话组件也会停靠进浅色行程工作区，所以以上换色挂在 `.wanderly-cosmos-chat` 作用域上：该作用域把 `--card`、`--muted-foreground`、`--border` 等语义别名重指向深空调色板，让面板内那些未被逐个点名的嵌套卡片自动跟随，而不必让每个组件各自感知模式。新增品牌色仍然禁止，作用域只重指向已有 token。

### 地图对话：活页旅行笔记实验

地图上的浮动对话可使用 `.wanderly-paper-chat` 作为这条规则的受控例外：它仍覆盖在真实地球与既有地图控件之上，但对话容器本身是一张浅雾白、四角小圆角的横线纸，而不是替换地图的独立页面。顶部控制直接落在同一张纸面上；只保留一排打孔，并在每个孔上方以不同的短撕裂边连接到纸张顶部，绝不加入横跨整张纸的撕裂条、Header 底色、分割线、阴影或锯齿状下沿。浅蓝色左页边线与横线一起构成笔记纸材质，但不显示标题或日期。打孔与顶部撕裂边不随消息区滚动。

纸内的横线与左页边线属于滚动区，和消息共同移动。所有常规正文行共用 `30px` 行高，并以 `2px` 写字偏移保持文字落在横线带的中下方；不得让 Markdown 段落额外改变普通行距。Agent 消息靠左、用户消息靠右，均无独立填充气泡。收起态输入框是露出视口的撕页首，纸张主体延伸到地图视口下方；展开时仅纸张面板从该页首向上拉出，收起时同一面板向下返回。地图地球、镜头和其他控件不参与此变换；动画仅使用 `transform` 与 `opacity`，并可在 `prefers-reduced-motion` 下停用。

## 布局与响应式规则

- 固定侧栏会脱离 Grid 正常流。桌面端标准页面的主内容必须显式指定其网格列；全屏探索地图应跨越所有外层列，让侧栏以浮层形式覆盖地图。地图左侧的品牌卡和可拖拽元素必须避开该浮层。工作区的历史栏、对话和检查器也分别指定列，避免自动布局把内容排入 64–88px 的导航列。
- 所有 Grid/Flex 子项都应允许收缩（`min-width: 0`），搜索框、标题和对话文本不得制造水平滚动。
- 卡片栅格在平板收为两列、在手机收为一列；抽屉在手机从底部弹出，不遮挡导航和主要地图控件。
- 保留跳转链接、可见键盘焦点和减少动态效果的媒体查询。图标按钮保持至少约 40–44px 的可操作尺寸。

## 实施检查清单

- 是否复用了上述 token，而非在组件中新增任意品牌色？
- 是否让正文保持深色（宇宙深色浮层除外），并保持足够对比度？
- 是否同时应用描边、不规则圆角和硬边投影，而不是只复制其中一项？
- 固定侧栏是否有对应的显式 Grid 列与移动端回退？
- 宇宙地图的浮层是否均为深色半透明，固定星点不会遮挡操作，且没有光束、阴影或背景光晕？
- 宇宙地图的浮层内部是否也没有白卡，包括对话气泡、操作卡、输入框和嵌套的结果卡片？
- 是否在 375px、768px、1024px 和 1440px 宽度下检查无横向溢出？

## 已知限制

本规范描述的是原型层面的 CSS 语言，未定义生产设计令牌的构建流程、深色模式全局策略或真实数据状态。生产实现仍须遵守 `docs/PRD.md`、`TECH_STACK.md` 和既有的无障碍、隐私与状态权威约束。
